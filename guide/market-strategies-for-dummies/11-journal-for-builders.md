# 11. How to journal so builders can learn from you

← [Checklist](10-one-page-checklist.md) · [TOC](README.md) · [Next: Mistakes →](12-common-mistakes.md)

---

You are not only learning to trade. You are generating **observation data** for the insight system (friction, confusion, near-misses, language mismatches). That is the guinea-pig loop — said with respect.

## Minimum viable journal entry

Copy for each idea (taken or skipped):

```text
ID:          (date-market-#)
Market:
TF_context:
TF_entry:
Stance:      trend_up | trend_down | chop | unsure
Location:    (level description)
Confirm:     (closed-candle proof or "none")
Pattern_tag: (optional)
Action:      taken | skipped
Skip_reason: (if skipped)
Invalidation:
Outcome:     win | loss | BE | n/a
Process:     A | B | C
Confusion:   (what felt unclear — be specific)
Screenshot:  (link/filename)
Builder_flag:(optional) "detector_disagreed" | "ui_confusing" | "term_unclear" | "wanted_alert"
```

## What builders will mine

| Your field | Why it matters |
|---|---|
| Stance + skip_reason | False opportunity rate / regime confusion |
| Confirm empty but Action taken | Protocol violations (product + coaching) |
| Confusion | Docs UX, glossary gaps, GUI labels |
| Builder_flag | Direct friction events for the capability loop |
| Screenshots | Ground truth vs automated geometry |

## Cadence

- During learning: **every session**  
- After week 1: weekly 10-minute retro with a builder (or solo summary)

## Privacy

Don’t put exchange passwords, API keys, or personal financial account numbers in journals. Market screenshots and process notes only.

## Practice

Submit (or save) **five** complete entries using the template — including skipped ideas.
